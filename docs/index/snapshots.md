# Extension 索引启动快照

## 背景与目标

Halo 在注册 Extension 类型时，从数据库读取该类型的全部资源并构建内存索引。Halo 重启和插件重新注册类型都会重复这一过程，数据量较大时，读取、反序列化和索引构建会增加启动耗时。

索引快照在安全的生命周期节点保存已经构建好的索引，使 Halo 和插件在下次注册相同类型时能够直接恢复。数据库仍是唯一数据源，快照是可以丢弃的启动缓存。快照不可用时，全量重建受影响类型的全部索引，不进行差量恢复或部分索引重建，也不改变运行期间的索引校验和事务语义。

本设计假定单个 Halo 实例拥有数据库写入权。直接 SQL、外部程序和绕过存储层的迁移不在自动一致性保障范围内，这些操作必须在修改数据前显式使快照失效。

## 快照与检查点

每个 Extension 类型使用一个压缩二进制文件，统一存放在工作目录的独立子目录中：

```text
<work-dir>/indices/snapshots/<Extension 完整类名>.snapshot.gz
```

文件包含该类型的完整索引集合、索引定义指纹和本次保存生成的随机标识。单值、多值和标签索引分别保存恢复查询所需的键、资源名称以及空值信息。恢复后的过滤和排序语义与重新构建一致；多值索引使用最小键作为排序代表值。

数据库同时保存一个检查点，名称为 `/system/index-snapshots/<存储前缀的 SHA-256>`，内容绑定资源类名、GVK、公共索引引擎兼容版本和文件随机标识。检查点使用现有 Extension 存储，无需新增数据库表。以实际存储前缀为单位，可以隔离不同资源类型，也能在插件未启动、类型尚未注册时定位需要失效的检查点。

仅有快照文件不足以恢复索引。必须同时存在可用的数据库检查点，且资源身份、随机标识、编码格式和完整索引定义均匹配，才允许使用文件中的数据。

## 类型注册与恢复

Halo 核心类型和插件类型共用以下注册流程：

1. 暂停该存储前缀的新写入，并等待已进入的写事务完成。
2. 读取并删除数据库检查点，确认删除完成后，才尝试恢复或重建。检查点在使用前即被消费，避免进程恢复后异常退出仍留下旧快照的使用资格。
3. 检查快照的资源身份、格式、随机标识及完整索引定义。全部兼容时恢复内存索引，无需查询该类型的业务记录。
4. 检查点缺失、文件不可用或校验不通过时，从数据库全量重建该类型。
5. 初始化成功后标记索引就绪，恢复该类型的快照保存资格并开放写入。

查询在索引初始化期间等待就绪，不读取部分构建结果。初始化失败会移除部分索引，回滚类型注册并通知清理监听器，后续注册可以重新尝试。每轮构建拥有独立的完成结果，旧一轮的等待者不能因为下一轮重试成功而读取其构建中间态。等待超时或中断会向调用方返回错误。

数据库检查点读取、消费失败或写事务无法排空时，注册失败，不把这类错误当成普通的缓存缺失继续运行。只有能够确定数据库和内存索引状态的类型，才能进入可查询状态。

## 写入与一致性

索引更新仍位于现有数据库事务流程中，保留唯一性、非空等索引约束的校验位置。事务完成回调只用于判断快照是否安全，不在提交后重新执行索引更新。

`IndexSnapshotWriteBarrier` 按存储前缀记录正在进行的写入，并跟踪到事务最终完成。注册、恢复、保存和注销持有同一类型的写入保护；保护期间新写入会失败，不阻塞响应式事件循环等待。已有写入必须完成后才能捕获索引或移除索引，排空超时或中断会中止该次生命周期操作并使快照资格失效。

|         写入结果         |             快照处理              |
|----------------------|-------------------------------|
| 正常索引维护路径的事务成功提交      | 保留保存资格；已有检查点在数据变化前失效          |
| 存储尚未返回结果便失败，例如乐观锁冲突  | 不因这次失败取消保存资格                  |
| 存储返回结果后事务回滚、取消或结果不确定 | 取消受影响类型的保存资格，避免保存可能与数据库不一致的索引 |
| 未经过索引维护路径的直接存储写入     | 使受影响类型失效，不能把旧内存索引发布为新快照       |
| 插件停用期间或类型尚未注册时写入     | 在同一事务中先删除可能关联的检查点，再修改数据       |

对未注册类型的写入会检查存储名称对应的候选前缀，覆盖资源名称包含斜杠的情况。检查点删除的内存状态只在确认提交后更新，事务回滚不能留下错误的“已删除”标记。已初始化且没有检查点的活跃类型，普通写入无需额外查询检查点。

失去保存资格后，成功的全量重建可以重新建立可信索引。该机制防止把已知不确定的内存状态保存到下一次启动，并不额外修复本来就发生在运行期间的事务或索引错误。

## 快照保存与停机顺序

类型注销时，先排空写入，在索引仍然存在时保存快照，再移除内存索引，整个过程保持写入保护。同一进程可以重复执行插件停止、启动和快照恢复。

保存顺序如下：

1. 导出该类型的完整索引，生成新的随机标识。
2. 写入快照目录中新建的独占临时文件，完成后原子替换正式文件。
3. 再次确认该类型仍可保存快照，在数据库中预留一个不可用于恢复的空检查点。
4. 通过带版本检查的更新，将资源身份和随机标识发布到检查点。

文件先完成、检查点后发布，避免数据库指向尚未写完的文件。检查点发布前就记录其可能已经存在，即使数据库响应超时，后续写入仍会删除它。迟到的发布只能更新原有版本，不能在数据已变化后重新插入有效检查点；迟到的预留最多留下不可用的空标记。再次保存遇到已有预留时，读取其当前版本后更新，避免永久无法保存。

文件保存或检查点发布失败会记录原因并取消该类型的保存资格，仍允许后续注销。根停机保存后，如果类型销毁再次触发保存且没有发生写入，复用已发布的一代，不重复替换文件或检查点。

Halo 正常关闭时按以下顺序执行：

```text
停止插件并清理插件声明的资源
    ↓ 插件类型注销时捕获自己的快照
停止核心控制器
    ↓
保存剩余核心类型的快照
    ↓
注销类型、销毁索引和存储组件
```

插件停止阶段保留原有内置资源清理逻辑，包括 `do-not-overwrite` 例外。此时核心控制器和垃圾回收仍能完成资源删除，避免下一次插件启动失败或离线升级移除声明后，旧登录方式等资源继续生效。

插件和共享上下文由根应用统一关闭，不再注册相互竞争的 JVM 关闭钩子。生命周期组件通过延迟解析依赖，避免 Spring 的依赖关闭顺序覆盖上述阶段顺序。剩余核心快照只在根应用达到就绪状态后保存；若保存后仍有关闭回调写入数据，对应检查点会先失效。

## Halo 与插件升级

是否复用快照取决于资源身份和索引兼容性，不比较 Halo 构建标识、插件版本或整个 JAR 的内容。仅调整页面、业务逻辑或其他不影响索引的代码，不会因此触发全量重建。

索引定义指纹包含索引名称、单值或多值类型、键类型、唯一性、空值约束及显式语义版本。任意索引新增、删除或指纹变化，都会重建该资源类型的全部索引，其他类型可以继续恢复。内置标签索引具有单独的指纹。

**索引取值函数的语义变化必须递增索引版本，Halo 核心与插件遵循同一规则。** 例如将索引键由原始值改为小写值，即使索引名称和键类型相同，也必须通过 `IndexSpecs.single(...).version(n)` 或 `IndexSpecs.multi(...).version(n)` 更新版本。结构指纹无法自动判断任意 Java 函数是否等价，遗漏版本变更可能导致错误复用。

公共索引行为变化由维护者递增引擎兼容版本，文件编码变化由编解码格式版本控制。不兼容的历史快照自动重建，无需迁移用户数据。标准索引构建器支持显式版本；自定义构建器的默认版本方法保留兼容入口，对未实现的显式版本设置会明确拒绝。

## 异常恢复与备份

|           场景            |                   恢复行为                    |
|-------------------------|-------------------------------------------|
| 首次启动、没有快照或检查点           | 全量重建该类型                                   |
| 文件缺失、截断、校验失败、标识不匹配或格式过旧 | 丢弃恢复结果并重建该类型；下次成功保存替换旧文件                  |
| 进程异常退出                  | 已注册类型的检查点已被消费，下次重建；未注册且没有数据变化的类型仍可保留有效检查点 |
| 磁盘空间不足、目录不可写或原子替换失败     | 放弃该次保存；存储条件恢复、类型成功重建后，正常生命周期重新生成快照        |
| 初始化失败或中断                | 清理部分索引并使等待者失败，允许后续正常注册重试                  |
| 写入结果不确定或排空超时            | 取消相关类型的复用资格，后续成功重建后恢复                     |
| 从备份恢复数据                 | 先全局禁止快照发布并等待在途快照生命周期结束，再替换数据              |

编解码器校验格式、长度、UTF-8 和文件完整性，不根据文件声明的条目数预分配大集合，避免截断文件仅凭伪造计数触发大内存分配。保存使用新临时文件，不复用残留路径；清理旧临时文件和符号链接时不跟随链接，不删除目录，清理失败不阻止正常写入尝试。

数据库检查点不进入备份，包括历史检查点命名空间。恢复数据后不能沿用恢复前的索引状态，后续重新构建并生成新快照。文件本身不作为业务数据备份或迁移的依据。

用户通常不需要手动删除 `snapshots`。损坏和不兼容由系统重建处理；权限、容量等外部存储问题仍需恢复运行条件，插件自身的启动错误也不由快照机制自动修复。

## 代价与边界

快照把一部分启动读取和索引构建成本转移到停止时的磁盘写入，并增加导出所需的临时内存和磁盘空间。它不会减少运行期间索引本身的内存占用，也不保证插件切换期间请求无中断。

一致性依赖单实例写入、受支持的存储路径、事务完成状态和正确的索引版本维护。缓存缺失或不可信时优先重建，不能为了启动速度继续使用无法证明有效的快照。
