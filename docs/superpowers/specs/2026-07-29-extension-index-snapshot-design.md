# Extension 索引启动快照

行为契约、设计和验收任务见 [OpenSpec 变更](../../../openspec/changes/clean-shutdown-index-snapshots/proposal.md)。Halo 和插件使用同一套按资源类型的生命周期。

- 快照保存于 `<work-dir>/indices/snapshots/`。数据库按实际存储前缀保存独立检查点，文件包含对应随机标识。
- 类型注册时暂停对应写入并等待已有事务完成，先消费数据库检查点，再验证资源身份、公共引擎兼容版本以及整个类型的索引定义指纹；匹配则恢复，否则全量重建该类型。
- 插件注销类型时，在同一写入保护下先保存快照、最后发布检查点，再移除内存索引。同一进程可以重复启停和恢复。
- 插件停用期间的存储写入也会使检查点失效，包括进程重启后尚未注册的类型、多级路径名称。事务回滚不能留下错误的“已消费”内存标记。
- Halo 和插件升级不再比较整个构建/JAR。索引结构、键类型、唯一性、空值约束及语义版本决定兼容性。新增、删除或改变索引时重建受影响类型。
- **Halo 和插件的 indexFunc 语义改变时，都必须递增现有索引版本。** 公共索引引擎语义改变时递增公共兼容版本。无法自动证明任意 Java 函数等价。
- 主应用关闭时，在核心控制器停止后的独立生命周期阶段停止插件并保存剩余类型，随后才销毁 Bean。插件及共享上下文不再注册独立 JVM 关闭钩子，由根应用按顺序关闭，避免并发注销类型。此时不执行插件热停用的内置资源清理；后续关闭回调如果仍写入数据，会先使对应快照失效。
- 乐观锁冲突在存储结果发出前回滚不影响正常索引维护路径的资格；已发出结果后回滚、未知事务结果、无索引维护的直接存储写入和等待超时使受影响类型失效。成功全量重建可恢复该类型的资格。
- 备份恢复先禁止发布并等待在途快照生命周期结束，再替换数据；所有快照检查点均排除在备份之外。异常退出时，已启用类型的检查点早已消费，不会恢复过期状态。

保留原有索引校验和数据库事务位置。没有差量恢复、部分索引重建、逐行版本清单或 afterCommit 索引写入。数据库是唯一数据源，快照可以丢弃。假定单个 Halo 实例拥有数据库写入权；直接 SQL 或迁移绕过存储路径时必须显式使快照失效。
